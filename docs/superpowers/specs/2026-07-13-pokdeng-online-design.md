# Spec: ป๊อกเด้งออนไลน์ (Pok Deng Online)

- **วันที่:** 2026-07-13
- **สถานะ:** อนุมัติแล้ว (รีวิวผ่านการสนทนา 3 ส่วน: กติกา / ดีไซน์ไพ่ / สถาปัตยกรรม)
- **ต้นแบบแนวคิด:** [Scrum-Poker-Online](https://github.com/yutinfo/Scrum-Poker-Online) — Vanilla JS + Firebase Realtime Database, ห้องแบบ room code, ไม่ต้องสมัครสมาชิก

## 1. เป้าหมาย

เกมป๊อกเด้งเล่นออนไลน์พร้อมกันหลายคนผ่านเบราว์เซอร์ แชร์รหัสห้องให้เพื่อนเข้ามาเล่นได้ทันที ไพ่ทุกใบ "หน้าตาเหมือนไพ่จริง" แต่วาดด้วย CSS + emoji ล้วน ไม่ใช้ไฟล์รูปภาพเลย

### Non-goals (ตั้งใจไม่ทำ)

- ไม่มีเงินจริงทุกรูปแบบ — ชิปเสมือนเท่านั้น ไม่มีระบบจ่ายเงิน ไม่มีการแลกเปลี่ยน
- ไม่มีระบบสมัครสมาชิก/โปรไฟล์ถาวร (ใช้ Firebase Anonymous Auth)
- ไม่มี chat แบบพิมพ์ข้อความ (มี emoji reaction ใน phase polish)
- ไม่มี bot เล่นแทน
- ไม่ป้องกันการโกงระดับ production — security rules กันการแอบดูไพ่ระดับ "เล่นกับเพื่อน" ตามที่ตกลง (เครื่องเจ้ามือเป็นผู้แจกไพ่ จึงเห็นข้อมูลรอบนั้นทั้งหมดโดยธรรมชาติ)

## 2. กติกาเกม (ruleset ที่เลือกใช้)

### 2.1 โครงห้องและชิป

| หัวข้อ | ค่าที่ใช้ |
|---|---|
| ผู้เล่นต่อห้อง | สูงสุด 9 คน (เจ้ามือ 1 + ผู้เล่น 1–8) |
| ชิปเริ่มต้น | 1,000 ชิปต่อคน |
| เติมชิป | กดเติมได้ครั้งละ 1,000 เมื่อชิปต่ำกว่าเดิมพันขั้นต่ำของห้อง (นับจำนวนครั้งเก็บในสถิติ) |
| เดิมพัน | ผู้เล่นเลือกเองต่อรอบ ภายใน min–max ของห้อง (ค่าเริ่มต้น 10–200, เจ้ามือแก้ได้ตอนอยู่ lobby/ระหว่างรอบ) |
| ชิปผู้เล่น | ติดลบไม่ได้ — ถ้าแพ้ด้วยตัวคูณแล้วชิปไม่พอ เสียเท่าที่มี (all-in cap) |
| ชิปเจ้ามือ | ติดลบได้ (แสดงตัวแดง) เพื่อให้จ่ายผู้ชนะได้ครบเสมอ — เจ้ามือกดเติมได้เมื่อชิปต่ำกว่า minBet (รวมกรณีติดลบ) เงื่อนไขเดียวกับผู้เล่น |

### 2.2 การนับแต้ม

- A = 1, ไพ่ 2–9 = ตามหน้าไพ่, 10/J/Q/K = 0
- แต้มมือ = ผลรวม mod 10

### 2.3 ป๊อก

- ไพ่ 2 ใบแรกรวมได้ 8 หรือ 9 = "ป๊อก" — เปิดหงายทันที จั่วเพิ่มไม่ได้
- เจ้ามือป๊อก = จบรอบทันที ทุกขาเทียบไพ่เท่าที่มีในมือ (2 ใบ) กับเจ้ามือ
- ป๊อก 9 ชนะ ป๊อก 8

### 2.4 เด้ง (ตัวคูณ) และประเภทมือ

| ประเภทมือ | เงื่อนไข | ตัวคูณ |
|---|---|---|
| สองเด้ง (2 ใบ) | ดอกเดียวกัน หรือ เลข/หน้าเดียวกัน | ×2 |
| ตอง (3 ใบ) | เลขเดียวกันทั้งสามใบ | ×5 |
| สเตรทฟลัช (3 ใบ) | เรียงลำดับ + ดอกเดียวกัน | ×5 |
| เรียง (3 ใบ) | ลำดับติดกัน (A-2-3 ได้, Q-K-A ได้, K-A-2 **ไม่ได้**) | ×3 |
| เซียน (3 ใบ) | J/Q/K ล้วน (คละได้) | ×3 |
| สามเด้ง (3 ใบ) | ดอกเดียวกันทั้งสามใบ | ×3 |
| ธรรมดา | นอกเหนือจากด้านบน | ×1 |

หมายเหตุ: มือ 3 ใบที่เข้าหลายเงื่อนไข ใช้ประเภทที่ลำดับสูงสุด (เช่น สเตรทฟลัชนับเป็นสเตรทฟลัช ไม่ใช่เรียง+สามเด้งซ้อนกัน)

### 2.5 ลำดับการชนะ (เทียบผู้เล่นกับเจ้ามือเท่านั้น — ผู้เล่นไม่เทียบกันเอง)

```
ป๊อก 9 > ป๊อก 8 > ตอง > สเตรทฟลัช > เรียง > เซียน > แต้มธรรมดา (9 → 0)
```

- ประเภทเดียวกัน: เทียบแต้ม (ตอง/เรียง/สเตรทฟลัช เทียบค่าไพ่: ตอง K > ตอง 7; เรียง Q-K-A สูงสุด, A-2-3 ต่ำสุด)
- เซียน ชน เซียน = เสมอ (ไม่แยกย่อย J/Q/K)
- ประเภทและแต้มเท่ากัน = **เสมอ ไม่ได้ไม่เสีย** (ไม่เทียบเด้งเพื่อหาผู้ชนะ)
- **ฝ่ายแพ้จ่ายตามเด้งของฝ่ายชนะ:** ผู้เล่นชนะ → เจ้ามือจ่าย เดิมพัน × เด้งผู้เล่น; ผู้เล่นแพ้ → เสีย เดิมพัน × เด้งเจ้ามือ

### 2.6 ลำดับเหตุการณ์ใน 1 รอบ (state machine)

```
lobby → betting → dealing → acting → dealerTurn → reveal → settled → (betting รอบใหม่)
```

1. **betting** — ผู้เล่นวางเดิมพัน (ปุ่ม preset 10/20/50/100 + พิมพ์เอง, clamp ตาม min/max และชิปที่มี) ผู้เล่นที่ไม่วางเดิมพัน = นั่งดูรอบนั้น เจ้ามือกด "แจกไพ่" ได้เมื่อมีอย่างน้อย 1 คนวางเดิมพัน
2. **dealing** — เครื่องเจ้ามือสับสำรับ 52 ใบ (Fisher-Yates + `crypto.getRandomValues`) แจกคนละ 2 ใบรวมเจ้ามือ พร้อม animation แจกไพ่
3. **เช็คป๊อก** — ใครป๊อกเปิดหงายทันที; ถ้าเจ้ามือป๊อก ข้ามไป reveal เลย
4. **acting (30 วินาที)** — ผู้เล่นที่ไม่ป๊อกเลือก "จั่ว" (รับใบที่ 3) หรือ "อยู่" พร้อมกันทุกคน หมดเวลา = อยู่อัตโนมัติ
5. **dealerTurn (45 วินาที)** — เจ้ามือเห็นว่าแต่ละคนจั่วไปกี่ใบ (ไม่เห็นหน้าไพ่) แล้วเลือกจั่ว/อยู่ หมดเวลา = อยู่อัตโนมัติ
6. **reveal** — เปิดไพ่ทุกมือพร้อม animation พลิก 3D (ไล่จากผู้เล่นซ้ายไปขวา ปิดท้ายเจ้ามือ)
7. **settled** — เครื่องเจ้ามือคิดเงินทุกขาแบบ transaction, แสดง modal สรุปผลรอบ (ใครได้/เสียเท่าไร มือประเภทอะไร), เจ้ามือกด "รอบต่อไป" หรือ "กลับ lobby"

### 2.7 กติกาผู้เล่นเข้า-ออก

- เข้าห้องกลางรอบ: เป็นผู้ชม (spectator) อัตโนมัติ ร่วมเล่นได้เมื่อเริ่มรอบใหม่
- ออก/หลุดกลางรอบ: เดิมพันยังอยู่ในรอบ ระบบเล่นแทนแบบ "อยู่" เมื่อหมดเวลา กลับเข้ามาใหม่เล่นต่อได้ทันที (uid เดิมจาก anonymous auth ที่ persist ใน browser)
- ส่งต่อบทเจ้ามือ: ทำได้เฉพาะช่วง lobby/settled — เลือกผู้เล่นที่ online อยู่ ชิปของแต่ละคนติดตัวไปตามเดิม

## 3. ดีไซน์ไพ่ emoji (อนุมัติตาม mockup แล้ว)

หลักการ: **โครงเหมือนไพ่จริงทุกอย่าง แต่ลวดลายทั้งหมดคือ emoji + ตัวอักษร ไม่มีไฟล์รูป**

- สัดส่วนไพ่ 2.5:3.5 พื้นขาว (#fffdf6) มุมโค้ง ขอบบาง
- มุมบนซ้าย + มุมล่างขวา (หมุน 180°): ตัวเลข/ตัวอักษร rank + emoji ดอกเล็ก — rank สีแดง (♥️♦️) หรือดำ (♠️♣️)
- ดอก: ♠️ ♥️ ♦️ ♣️ (emoji มาตรฐาน)
- ไพ่เลข 2–10: วาง pip emoji ตามจำนวนจริง จัด layout ใกล้เคียงไพ่จริง (grid กลางใบ)
- A: ดอก emoji ใหญ่ใบเดียวกลางไพ่
- ไพ่หน้า (ในกรอบเส้นทองแบบไพ่จริง มีดอกเล็กบน-ล่างสะท้อนกัน): **J = 💂, Q = 👸, K = 🤴**
- หลังไพ่: พื้นน้ำเงินเข้ม กรอบใน + 🎴 กลางใบ
- เปิดไพ่: CSS 3D flip animation; แจกไพ่: animation ไพ่บินจากตำแหน่งเจ้ามือ
- การ์ดต้อง render ได้ 3 ขนาด: ใหญ่ (มือตัวเอง), กลาง (มือคนอื่นตอน reveal), เล็ก (ประวัติ/สรุปผล)

### โต๊ะเกม

- พื้นสักหลาดเขียว เจ้ามืออยู่บนสุด ผู้เล่น 8 ที่นั่งเรียงรอบล่าง/ข้าง
- แต่ละที่นั่ง: avatar emoji + ชื่อ + ชิปคงเหลือ + เดิมพันรอบนี้ + สถานะ (กำลังคิด…/อยู่/จั่วแล้ว/ป๊อก!) + ไพ่ (หลังไพ่จนกว่า reveal ยกเว้นมือตัวเองเห็นตลอด)
- แถบสถานะกลางโต๊ะ: state ปัจจุบัน + นาฬิกานับถอยหลัง
- avatar: ให้เลือกจาก emoji preset ~24 ตัว (สัตว์/หน้ายิ้ม) ตอนตั้งชื่อ
- Mobile-first responsive (ผู้เล่นส่วนใหญ่เล่นบนมือถือ) — desktop จัดเต็มโต๊ะ, มือถือย่อ seat เป็นแถว

## 4. สถาปัตยกรรม

### 4.1 ภาพรวม

- **Frontend:** HTML + CSS + Vanilla JS (ES Modules) — ไม่มี build step, ไม่มี framework
- **Firebase:** Anonymous Auth + Realtime Database (Spark plan ฟรี), SDK โหลดจาก CDN (`https://www.gstatic.com/firebasejs/…` แบบ ES module)
- **ไม่มี backend ของตัวเอง** — เครื่องเจ้ามือ (dealer client) คือ game engine: สับไพ่ แจกไพ่ ตัดสินผล คิดเงิน
- **Deploy:** static hosting (Vercel หรือ Firebase Hosting)

### 4.2 โครงข้อมูล Realtime Database

```
rooms/{ROOMCODE}
├─ meta: {
│    createdAt, hostUid,            // hostUid = เจ้ามือปัจจุบัน
│    state,                          // lobby|betting|dealing|acting|dealerTurn|reveal|settled
│    round,                          // เลขรอบปัจจุบัน (int, เริ่ม 1)
│    minBet, maxBet,
│    turnDeadline                    // epoch ms ใช้วาดนาฬิกา (client เทียบเวลาตัวเอง)
│  }
├─ players/{uid}: {
│    name, avatar, chips, seat,      // seat = ลำดับเข้าห้อง (0-7), เจ้ามือไม่ใช้ seat
│    online, lastSeen, rebuys,
│    joinedRound                     // ไว้ตัดสิน spectator (เข้ากลางรอบ)
│  }
└─ rounds/{n}
   ├─ deck: [ {r,s}, … ]            // ไพ่ที่ยังไม่แจก — อ่าน/เขียนได้เฉพาะเจ้ามือ
   ├─ bets/{uid}: number
   ├─ hands/{uid}: [ {r,s}, {r,s}, {r,s}? ]
   ├─ actions/{uid}: "hit"|"stay"
   └─ results/{uid}: { delta, rankName, deng, points }
```

- รหัสห้อง 6 ตัวจากชุด `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (ตัด 0/O, 1/I กันสับสน) — เข้าห้องผ่านฟอร์มหรือ URL `?room=CODE`
- ไพ่แทนด้วย `{r: 1-13, s: "s"|"h"|"d"|"c"}`
- เก็บ `rounds` ย้อนหลังสูงสุด 5 รอบ — dealer engine ลบรอบเก่ากว่านั้นตอนเริ่มรอบใหม่

### 4.3 การแบ่งหน้าที่ read/write (บังคับด้วย Security Rules)

| path | อ่าน | เขียน |
|---|---|---|
| `meta` | สมาชิกห้อง | เจ้ามือ (hostUid เขียนได้เมื่อ takeover — ดู 4.5) |
| `players/{uid}` | สมาชิกห้อง | เจ้าของ uid (สมัคร/heartbeat/เติมชิป +1,000) และเจ้ามือ (จ่ายเงินตอน settle) |
| `rounds/n/deck` | เจ้ามือเท่านั้น | เจ้ามือเท่านั้น |
| `rounds/n/bets/{uid}` | สมาชิกห้อง | เจ้าของ uid เฉพาะช่วง state=betting, จำนวนภายใน min/max และ ≤ chips |
| `rounds/n/hands/{uid}` | เจ้าของ uid + เจ้ามือ; ทุกคนเมื่อ state=reveal/settled | เจ้ามือเท่านั้น |
| `rounds/n/actions/{uid}` | สมาชิกห้อง (เห็นสถานะจั่ว/อยู่) | เจ้าของ uid เฉพาะช่วง state=acting, เขียนซ้ำไม่ได้ |
| `rounds/n/results` | สมาชิกห้อง | เจ้ามือเท่านั้น |

ระดับการป้องกันนี้ = "casual-grade": ผู้เล่นทั่วไปแอบดูไพ่คนอื่นผ่าน DB ไม่ได้ แต่เครื่องเจ้ามือเห็นทั้งหมด (จำเป็นเพราะเป็นผู้แจก) — ยอมรับแล้วตามการตัดสินใจตอน brainstorm

### 4.4 Dealer engine (js/dealer.js — ทำงานเฉพาะเครื่องเจ้ามือ)

- เริ่มรอบ: สร้างสำรับ 52 ใบ → Fisher-Yates ด้วย `crypto.getRandomValues` → เขียน `deck` → แจก `hands` ทีละคน (ผู้เล่นที่วางเดิมพันแล้วเท่านั้น) → เช็คป๊อก → ตั้ง state ถัดไป + `turnDeadline`
- ระหว่าง acting: listen `actions/*` — ใครกด hit ก็ pop ไพ่จาก deck เขียนต่อท้าย hand ของคนนั้น เมื่อครบทุกคนหรือหมดเวลา → dealerTurn
- Timer ทำงานที่เครื่องเจ้ามือ (setTimeout เทียบ turnDeadline) — client อื่นแค่วาดนาฬิกาจาก turnDeadline
- settle: ประเมินทุกมือด้วย `pokdeng.js` → คำนวณ delta ต่อคน (รวม all-in cap ของผู้เล่น) → เขียน `results` + อัพเดต `chips` ทุกคนแบบ multi-path atomic update ครั้งเดียว → state=settled
- เจ้ามือรีเฟรชกลางรอบ: อ่าน deck + state จาก DB กลับมาแล้วทำงานต่อได้ (engine เป็น stateless resume)

### 4.5 Presence และความทนทาน (ตามหลัก Scrum-Poker-Online)

- ทุก client: heartbeat อัพเดต `lastSeen` ทุก 25 วินาที + `onDisconnect().update({online:false})`
- **เจ้ามือหลุด:** เกมค้างที่ state เดิม — ถ้า `lastSeen` ของเจ้ามือเก่ากว่า 60 วินาที ผู้เล่นทุกคนเห็นปุ่ม "รับเป็นเจ้ามือแทน" คนแรกที่กดได้เป็น (security rule ยอมให้เขียน hostUid เมื่อเจ้ามือเดิม stale) → รอบปัจจุบันยกเลิก คืนเดิมพันทุกคน กลับ lobby
- **ห้องร้าง:** ตอน join ถ้าพบว่าห้องมีอยู่แต่ทุกคน `lastSeen` เก่ากว่า 24 ชม. ให้ลบห้องแล้วสร้างใหม่ได้ (client-side sweep)
- ชิป/การเขียนสำคัญใช้ transaction หรือ atomic multi-path update กัน race และกันกดซ้ำ (เช่น กดจั่วรัว ๆ ได้ไพ่ใบเดียว)

## 5. การทดสอบ

1. **Unit tests (`node --test`)** ครอบคลุม `pokdeng.js` ทั้งหมด:
   - นับแต้ม mod 10 ทุกขอบเคส (0 แต้ม, A=1, 10/J/Q/K=0)
   - ป๊อก 8/9 เฉพาะ 2 ใบแรก, ป๊อกชนป๊อก, ป๊อกเสมอ
   - ทุกประเภทมือ 3 ใบ + ลำดับความสำคัญเมื่อเข้าหลายเงื่อนไข (สเตรทฟลัช vs เรียง vs สามเด้ง)
   - เรียง: A-2-3 ✓, Q-K-A ✓, K-A-2 ✗
   - ตารางเทียบชนะ/แพ้/เสมอ ครบทุกคู่ category
   - payout: เด้งฝั่งชนะ, all-in cap, เจ้ามือติดลบ, ผลรวม delta ทุกคน = 0 เสมอ (zero-sum invariant)
2. **Realtime manual checklist** (เปิดหลายแท็บ): สร้างห้อง → เข้า 3 คน → เล่นครบรอบ → ผู้เล่นรีเฟรชกลางรอบ → เจ้ามือรีเฟรชกลางรอบ → เจ้ามือหายแล้ว takeover → เติมชิป → ส่งต่อเจ้ามือ
3. **เดโม่จริงผ่าน browser** ตอนจบแต่ละ phase สำคัญ

## 6. ลำดับการ implement (7 phases)

1. **Foundation:** ลบไฟล์เว็บ Education Green เดิม, วางโครงไฟล์, เขียน `pokdeng.js` + unit tests ให้ผ่านครบ
2. **Room system:** firebase.js, room.js, หน้า landing (ชื่อ+avatar), สร้าง/เข้าห้อง, lobby แสดงสมาชิก realtime, presence
3. **Card & table UI:** cards.js วาดไพ่ emoji ตาม mockup, โต๊ะเขียว, seat layout, responsive
4. **Game loop:** dealer.js + game.js ครบ state machine — เล่นจบรอบได้จริงหลายคน
5. **Resilience:** reconnect/resume, host takeover + refund, เติมชิป, timer auto-stay, spectator, ห้องร้าง
6. **Polish:** animation แจก/พลิกไพ่, modal สรุปผล, สถิติ (กำไร/ขาดทุน, จำนวนเติม), เสียง (toggle ได้), emoji reactions
7. **Ship:** database.rules.json ฉบับเต็ม + ทดสอบ rules, README setup guide, deploy

ทุก phase จบด้วยของที่รันได้จริง — รายละเอียดงานย่อยจะอยู่ใน implementation plan (ขั้นถัดไป)

## 7. ความเสี่ยงที่รับทราบแล้ว

- **Trust model:** เจ้ามือเห็นไพ่ทุกคน (เป็นผู้แจกโดยสถาปัตยกรรม) — เหมาะกับเล่นสนุกกับเพื่อน ไม่เหมาะกับการแข่งขันจริงจัง
- **Timer อาศัยเครื่องเจ้ามือ:** ถ้าเครื่องเจ้ามือ sleep นาฬิกาหยุด — มี host takeover เป็น safety net
- **Emoji ต่างเครื่องต่างหน้าตา** (Apple/Google/Windows วาด 👸 ไม่เหมือนกัน) — ยอมรับได้ เป็นเสน่ห์ของธีม และโครงไพ่/สี/เลขเหมือนกันทุกเครื่อง
